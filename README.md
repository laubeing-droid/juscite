# 律引（Juscite）— 面向中文律师的本地法律工作台

> 会话和案件材料放在你自己的电脑上。起草、整理和解释会调用云端模型。能核对上的结论给出处，对不上就写明未命中或未连接。

当前版本 **0.1.0**，早期开发。接口还会变。先看你手头的难处、可以怎么开口，以及这一版明确还没接上的边界。

## 从手头的工作说起

卷宗、合同、判决书整段贴进通用在线工具，回来的常常是一段流畅、却对不上原文的话。模型很多，不知道先用哪个；提问也不像在办一件具体的事。整卷材料对不齐，真实文件能不能交出去心里没底，回答又不敢直接拿去用。

律引把这些收成工作台里的一件事：从你正在做的那项工作开口。同一件案子的材料尽量留在本机上看。出处、有没有核上、以及要不要采纳，分开写清楚。

律引不是判官，也不替代律师判断。可以机械核验的部分交给代码，判断留给你。

### 可以这样说

**「从这批附件里整理出关键事实，并标上各自的日期。」**

法律工作台里可以在时间线上整理这些关键事实，标上各自的日期，再回到原文核对。这是面板上的整理。客户档案、利益冲突和开庭日程没有接成同一条办案后台。

**「按本案材料起草一份文书。」**

起草由 AI 出稿，推理发到云端模型。稿子留在工作台里阅读和修改。这一轮没有接到 Word 或 WPS，也不会从对话推进到办公软件里的文档。

**「核一下这段话里的法条引文。」**

引证核验由确定性代码对照随包的本地法条数据。对上了就附出处；没有就报告未命中或未连接，不另编一条。法条入口仍有合成桩。这里没有接上全国法规库，也没有实时法条接口。

## 边界

读后面的功能之前，先看这一版不能这么说的事。

1. **流程。** 本轮桥侧流程运行时是 FlowGate（流程闸门）与 quote-back（引文回验）。整套 flow 引擎不装配进桥宿主。office-bridge 这一轮没有接线。Word / WPS 办公对接不算已集成。
2. **法条。** 没有接上国家法律法规数据库或在线法条接口。法条入口仍有合成桩。随包的本地法条数据可以检索，效力按包内数据做确定性判断；包损坏会显示不可用。这不是官方库的实时连接。
3. **规章与合规。** 没有单独接上的确定性规章检查引擎。这类检查仍在模型工具面上。
4. **监听地址。** 桌面应用会拉起本地桥，界面经 WebSocket 连接（开发文档中的端口是 3030）。桥的 listen 没有绑定 127.0.0.1，不能把「只听本机回环」当成安全保证。
5. **数据与模型。** 「材料留在本机」指会话和案件库存本地 SQLite 与本地文件。起草、解释和检索研究的推理会发到云端模型，内置目录中的名称包括 GLM-5.2、GLM-5.3。不是全程离线。模型通道需要自行接上。
6. **判断。** 律引不是判官，不替代律师判断。模型可能写错、写漏。要不要采纳，由你决定。
7. **安装形态。** 这一轮对外安装包按 Windows 准备。

法律工作台顶上有的总览区块仍是合成演示数据。看到一块面板，只说明界面上有这个入口。

## 功能全景

### 办案面板

- **法律工作台**：对照材料、看时间线、起草文书、用法条手册、做引证核验和文档对比。顶上部分总览仍可能是合成演示。
- **知识库**：浏览本机知识库。向它提问时，推理走云端模型。
- **检索研究**：围绕一个问题做研究整理，推理走云端模型。
- **电子证据**：电子证据面板，包含锚定、表格、审阅、任务。
- **流程工作室**：工作台上的流程面板。桥宿主里装配的是 FlowGate 与 quote-back，整套 flow 引擎不在其中。
- **利益冲突预检**、**团队协作**、**安全审计中心**：面板入口。不表示客户、冲突、日程已经串成一条办案后台，也不在这里展开审计记录的字段。

### 代码负责核验的三件事

引证核验、法条效力、文档对比由确定性代码完成，不交给模型编造。结果要么附出处，要么写明未命中或未连接。法条侧的限制见「边界」。

### 模型负责起草和解释

AI 起草、整理、解释，也用于检索研究。调用云端模型，内置目录里有 GLM-5.2、GLM-5.3 这类名称。生成经自有能力合同接到现有的 OpenCode 适配器。采不采纳由律师决定。

## 快速开始

前提：Node.js（建议 22 或更新）、pnpm 10（仓库经 `packageManager` 钉定 pnpm@10.33.2）。Python 3.12+ 只在使用 Python 能力面和辅助脚本时需要。

```bash
# 在仓库根目录
corepack enable
pnpm install
pnpm typecheck
node tools/bridge/ci_gate.mjs fast
pnpm dev:web
```

`pnpm typecheck` 做类型检查。`node tools/bridge/ci_gate.mjs fast` 覆盖桥源码语法、UI 合同测试、桥端到端测试、合成自测和品牌检查，退出码 0 表示这道门通过。版本仍是早期开发。

`pnpm dev:web` 启动 Web 版工作台的开发服务器。

桌面应用这一轮按 Windows 准备：

```bash
pnpm build:desktop
python scripts/launch_desktop_trial.py
```

`pnpm build:desktop` 做桌面生产构建。`python scripts/launch_desktop_trial.py` 先确认构建产物和本机 Electron 在位，再以产物模式拉起。Windows 下建议用这个入口。仓库根目录没有不暴露内部包名的桌面热更新脚本，所以这里不写开发态的桌面启动命令。

预期结果和常见问题见[快速上手](docs/getting-started.md)。

## 工作原理

**桌面壳**（Electron）承载 **工作台界面**。界面通过 WebSocket 连接 **本地桥**：一个在本机运行的 Node 进程，上面有法条手册、引证核验、文档对比、电子证据等服务，数据写入本地 SQLite。流程侧本轮接到桥上的是 FlowGate 与 `@juscite/flow` 的 quote-back。整套 flow 引擎不装配进桥宿主。office-bridge 这一轮没有接线。

桥再经一层自有的能力合同，接入钉定版本的 AI 运行时（现有适配器是 OpenCode）。起草和解释会把内容发到云端模型。另有一个 Python 能力面，只从固定白名单入口连接外部确定性引擎；没配好就显示未连接，不伪造成功。

组件图和一次请求怎么走，见[架构概览](docs/architecture.md)。读图时以上面的边界为准：整套 flow 引擎和 office-bridge 这一轮都没有接进桥宿主；桥的 listen 也没有绑定 127.0.0.1。

## 项目结构

| 目录 | 内容 |
|---|---|
| `packages/` | 工作区包：桌面壳、工作台界面与自有功能包。职责见[自有包](docs/packages.md) |
| `tools/bridge/` | 本地桥：`bridge_host.mjs`（入口）与 `ci_gate.mjs`（验证门禁） |
| `implementation/python/` | Python 能力面：`legal_entry.py` 冻结白名单入口及功能模块 |
| `lawbook-packs/` | 内置法条数据包（公有领域法律文本，完整性校验）。不是在线法规库 |
| `contracts/` | 机器可读的边界合同（注册点、引用图、类型快照等） |
| `config/` | 客户端内置默认配置 |
| `scripts/` | 构建、引用图生成与启动辅助脚本 |
| `LICENSE` / `NOTICE` / `THIRD-PARTY-NOTICES.md` | 许可与第三方声明 |
