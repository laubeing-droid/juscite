# 电子数据取证审查（Juscite 预装）

对微信记录、转账/银行流水、业务表格三类电子数据完成"进场固定→锚定→归类→清单→审查"
的取证整理，产出带页/坐标锚、可回跳核验的审查标注与七节报告。
本技能只提供方法与格式合同，不替代律师对证据的判断；机器产出的档位与清单一律是建议档。

## 一、目的与三档原则

取证审查的目的是把散落的电子数据整理成"每一句引用都能回到原文位置"的证据材料，而不是替
裁判者下结论。每一份证据的审查结论落三档：

- **明显充分**：来源可查、内容完整、与待证事实直接对应。
- **存疑保留（默认档）**：有任何一处拿不准——来源存疑、内容不完整、缺少印证——都落这一档，
  并写清存疑的具体问题。双向门原则：宁可多标注交给律师判断，不可漏标。
- **明显不足**：只记录"建议不单独作为定案依据"的意见，**不自动排除任何证据**。

## 二、待证事实先行

审查任何电子数据之前，先从诉求与争点提炼待证事实清单；审查只回答"这份数据对哪个待证事实
有什么用"。下列内容不进待证清单：各方无争议的事实、已由生效文书确认的事实、纯法律适用问题、
公知事实。没有待证事实对应的数据仍进场、仍锚定，但审查档位至少落"存疑保留"。

## 三、形式六要素

每份数据先查六项形式要素，逐项登记：

1. 名称（这份材料叫什么、对应哪个源文件）；
2. 形成时间（数据生成/导出的时间，区别于内容里记载的时间）；
3. 出具方/来源（谁生成、从什么载体取得）；
4. 原件或复印件状态（导出件、截图、打印件各属什么）；
5. 证明目的（拟用它证明什么）；
6. 对应待证事实（对应第二节的哪一条）。

缺任何一项，标注"形式要素待补齐"，先补齐再实质审查。

## 四、三性评估与证明力标准

对每份数据按真实性、合法性、关联性逐项给结论和理由；证明力分四级：强／中／弱／无。

电子数据专项规则（五条，预置进工具的默认档）：

1. 经公证机关公证或可信时间戳认证的电子数据，真实性障碍基本消除，可落"明显充分"。
2. 未经公证的微信聊天记录、电子邮件、截图，默认落"存疑保留"，逐条标注两件事：
   能否用其他证据印证；是否需要申请电子数据司法鉴定。证明力预置为"弱"。
3. 真实性攻击预判必须包含"数据被篡改、删改、断章取义"方向；应对路径是补充印证证据或申请鉴定。
4. 同类问题集中出现的（例如"全部聊天记录均未公证"），合并为一个决定点统一标注，不逐条重复。
5. 流水与表格类数据：金额以原文为准（字符串原文+整数分双轨保存，禁浮点换算），换算结论
   一律注明口径与计算时间，不把换算写回原文。

## 五、举证责任与缺口

对每项待证事实先定举证责任在哪一方（按一般规则，注意法律明确倒置举证责任的情形），再对照
现有数据盘点四类缺口：完全缺口（没有任何数据）、证明力不足（有数据但偏弱）、证据链断裂
（中间环节缺失）、形式瑕疵（第三节要素不全）。每个缺口给补充建议：建议取得什么证据、从什么
渠道取得、对应哪个待证事实、收集难度如何；涉及期限的给硬性期限警示。

## 六、质证预判

对每份拟用数据预判对方可能的三性攻击方向（真实性、合法性、关联性各想一遍），并给出应对
策略。电子数据的攻击高频落在真实性上，按第四节第 3 条预判与应对。

## 七、引用核实双轮与来源标签

- 第一轮：提取全部引用并报总数；第二轮：逐条回到原文位置比对，**不抽样**；报告覆盖率。
  原文取不到的引用写"未能核查"，禁止写成"已确认"。
- 每条引用必须携带页/坐标锚（页码+坐标框+来源引擎+OCR 版本+源哈希），引用可回跳到原文位置；
  行类引用用（源、表、行区间）三件套+源哈希。
- 每处规则引用带来源标签；来自网络检索或模型知识的内容必须带"须核实"限定，不得删标签；
  检索不到就写检索不到，不得无声补充。

## 八、律师闸声明

本审查全部产出是**初步审查**。所有"存疑保留"与"明显不足"标注，须经执业律师逐项过目并
确认后，方可作为行动依据；机器没有任何豁免通道。非律师身份在"提交庭审/对外出示"前会触发
确认门。工具只负责定位、锚定、聚合、校验；定档与确认归人。

## 九、输出七节模板

审查报告按以下七节输出：

1. 待证事实清单；
2. 证据清单（逐份带锚与形式要素）；
3. 存疑标注清单（默认档重点，逐条带具体存疑问题）；
4. 不足记录（只记录意见，不执行排除）;
5. 缺口与补充建议（第五节四类缺口）；
6. 质证预判（第六节攻击方向与应对）；
7. 规律性观察（同类集中问题合并标注）。

报告附统一四类标记：核实／存疑／引用待定／举证期限警示，机器可识别、人可读。

## 十、局限声明

- 本技能产出是整理与审查辅助，不构成法律意见；证据的最终取舍由裁判者作出。
- 未经认证的电子数据证明力判断只是预置建议，个案可能因印证情况而显著不同。
- 本技能不保证"明显充分"档终局正确；不捏造法条与案例；引用不到原文就如实标注。
- 审查报告继承来源材料的保密属性，对外分发须慎重。
- 扫描件、图片类聊天记录需 OCR 才能锚定；本版未启用本地 OCR 时，此类材料如实标注"需 OCR"，
  不假装已锚定。
